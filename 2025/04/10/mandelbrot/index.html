无尽边界：Mandelbrot 集之美

Posted on 2025-04-10 Edited on 2026-04-23

很多人第一次看到 Mandelbrot 集时，都会被它的形状震住：

  • 远看像一只黑色的“心形甲虫”；
  • 近看边界卷曲、分叉、重复；
  • 再继续放大，新的结构还会不断冒出来。

它看起来非常神秘，但如果我们站在“程序是怎么画出它的”这个角度去看，事情其实很清楚：

  1. 先在复平面上取很多点；
  2. 对每个点做同样的迭代；
  3. 根据这个点“逃逸得有多快”给它上色；
  4. 最后把结果保存成一张图片。

这篇文章的目标，不是只给出一个能运行的 Mandelbrot 程序，而是把这段程序背后的每一步都讲透，尤其是最关键也最容易让人迷惑的一步：

程序到底是怎么在复平面里生成一整张图所需要的那些点的？

这一步理解了，Mandelbrot 集的程序就算真正入门了。

我们先把完整代码摆出来，后面再一段一段拆开。

二、Mandelbrot 集到底是什么？

Mandelbrot 集研究的是下面这个迭代：

\[ z_{n+1} = z_n^2 + c, \qquad z_0 = 0 \]

这里：

  • c 是复平面上的一个点；
  • z 是从 0 开始不断迭代出来的复数序列。

我们关心的问题只有一个：

对于某个给定的复数 c，从 z=0 开始不断迭代，z 会不会越跑越远？

如果它很快越跑越大，说明这个点在 Mandelbrot 集外面。 如果它怎么迭代都不明显发散，我们就把它视为 Mandelbrot 集内部，或者至少非常接近边界。

于是，绘制 Mandelbrot 图，本质上就是：

把复平面切成很多很多个点，对每个点都问一遍：你会不会逃逸？

程序最终画出来的，并不是一个“神秘的形状”，而是一个巨大的“判定结果图”。

四、最关键的一步：程序是怎么生成复平面中的点的？

这一节要讲透彻，因为它决定了你到底有没有真正看懂这段程序。

4.1 图像像素和复平面点之间的对应关系

一张图像是一个矩形网格：

  • 横向有 width 个像素；
  • 纵向有 height 个像素。

复平面中的观察区域，也可以看成一个矩形：

  • 横向对应复数的实部；
  • 纵向对应复数的虚部。

所以最自然的映射就是：

  • 图像每一列，对应一个实部；
  • 图像每一行，对应一个虚部；
  • 行和列一组合，就得到一个复数 c = 实部 + 虚部 * i。

这就是“图像采样”的本质。

这表示从复数 0 + 0i 开始。

十七、从“函数清单”到“程序思维”：这段 Mandelbrot 代码真正教会我们的是什么？

表面上看，这段程序用了很多工具：

  • 复数；
  • NumPy；
  • 广播；
  • 图像转换；
  • 即时编译。

但更深一层，它其实教会了我们一种非常重要的数值计算思维：

17.1 先把数学对象离散化

复平面原本是连续的，但计算机处理的是有限数组。

所以第一步永远是：

先把连续区域采样成有限网格。

17.2 再把单点规则推广成整张网格的规则

单个点的迭代公式很简单：

\[ z \mapsto z^2 + c \]

但真正画图时，你要让整张网格的每个点都经历这条规则。

17.3 最后把抽象结果翻译成可视化结果

数学上我们得到的是：

  • 这个点逃了还是没逃；
  • 它在第几步逃；
  • 它逃逸时的状态。

而图像上我们需要的是：

  • 这个像素是什么颜色。

也就是说，绘图程序本质上总是在做“数学世界”和“视觉世界”的翻译。

十八、给初学者的一个最简理解版本

如果你现在已经读到这里，但还想要一个极简版本，那我把整段程序压缩成三句话：

  1. 用 ogrid 生成实部和虚部采样值，并通过广播拼成复数网格。
  2. 对每个复数点 c，从 z=0 开始反复做 z=z*z+c，观察它是否逃逸。
  3. 把逃逸结果转成 RGB 颜色，再保存成 PNG 图。

因为这一步完成了从“图像像素”到“复数坐标”的真正映射。
