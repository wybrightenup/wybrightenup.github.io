第 28 章 动态规划: 把多阶段决策化为递推问题

有面值为 2, 5, 7 的教学硬币, 每种数量不限. 想恰好凑出 27, 最少需要几枚? 先用纸笔列几份方案, 再让程序把不同选择产生的小问题记下来. 这些面值是人为设定的算法数据, 不对应实际流通硬币体系.

本章沿着"核对一份方案, 计算一个状态, 填表, 记录选择, 还原方案"的顺序学习动态规划. 后面把相同思路用于社区科普装备选择, 再计算一个两阶段经费分配问题. 每个表格中的数都要先有明确含义, 才能决定怎样更新.

28.1 先核对方案: 凑得出来, 不等于已经最省

最大面值优先是一个容易想到的规则. 先拿三个 7, 剩余 6; 再拿一个 5, 剩余 1, 已经没有面值可用. 这份尝试失败, 原问题却仍然可能有解.

三枚及以下最多凑出 21. 四枚硬币最多凑出 28, 从四个 7 出发, 把某个 7 换成 5 或 2, 只能减少 2 或 5, 无法只减少 1. 所以四枚也凑不出 27. 已经有五枚方案, 最少枚数因此确认为 5. 这是本例独立于程序的最优性证据.

后面的动态规划要提供一种统一算法: 不只处理 27, 还要处理 0, 无法凑出的金额, 以及其他正整数面值组合.

28.2 只算一个格子: 凑出 9 的最后一枚是什么

28.2.1 先给保存的数起一个准确含义

定义

\[ f[x]=\text{使用给定面值恰好凑出金额 }x\text{ 的最少硬币枚数}. \]

无法凑出时, 记为 \(+\infty\). 假设已经得到金额 0 至 7 的结果:

表 28-2 金额零至七的已知最优值.

金额 \(x\) 0 1 2 3 4 5 6 7
\(f[x]\) 0 \(+\infty\) 1 \(+\infty\) 2 1 3 1

现在只求 \(f[9]\). 如果最后一枚是 2, 前面必须恰好凑出 7, 候选枚数为 \(f[7]+1=2\). 同样检查最后一枚为 5 和 7 的情况:

表 28-3 求金额九时的最后一枚选择.

最后一枚 前面的金额 前面最少枚数 加上最后一枚后的候选枚数
2 7 1 2
5 4 2 3
7 2 1 2

因此 \(f[9]=\min\{2,3,2\}=2\). 候选值分别属于不同分支, 不能把 \(f[9]\) 同时写成 2, 3 和 2. 最后为 2 或 7 都能达到最优, 对应 \(7+2\) 的不同排列.

Python 列表的下标与金额一致, 读取 known[7] 就是在查 \(f[7]\). MATLAB 从下标 1 开始, 数学金额 \(x\) 对应 known(x+1), 所以来源金额 \(9-c\) 要读取 known(9-c+1).

28.2.2 从一个格子写出递推

对正整数面值集合 \(C\), 当前金额为 \(x\) 时, 枚举最后一枚 \(c\):

\[ f[x]=\min_{\substack{c\in C\\c\leqslant x}}\{f[x-c]+1\}, \qquad x=1,\ldots,N. \]

如果没有合法分支, 或所有来源都不可达, 结果就是 \(+\infty\). 每份可行方案都有某个最后面值, 因而不会漏掉它所属的分支.

为什么分支内部可以直接使用最少枚数? 假设一个最优方案最后为 \(c\), 而前面的 \(x-c\) 还有更省的凑法. 把前面替换成更省的方案, 再补同一枚 \(c\), 整体就会更省, 与原方案最优矛盾. 这里的替换不受硬币供应影响, 因为每种数量不限. 这种替换论证解释了本例的最优子结构.

图 28-1 最少硬币问题的部分依赖. 箭头从待求金额指向所需的较小金额, 旁边标明减去的面值. 同一个子问题只画一个节点, 多条箭头汇入它时, 计算结果可以复用.

凑出 0 不需要硬币, 所以 \(f[0]=0\). 其他金额开始时先写成 \(+\infty\), 表示尚未找到可行方案. 然后从小金额向大金额更新.

先看代码的三步: 给一个候选值加 1, 与当前值比较, 再把较小值存回当前格子. 对一个金额试完所有面值, 才算完成这个状态. 金额逐个增加, 就把上一节的一次计算组织成了整个表格.

计算顺序为什么可行? 面值严格为正, 所以合法来源总满足 \(x-c<x\). 算当前格子时, 来源已经算好. 实际代码只在 \(c\leqslant x\) 时读取来源, 避免访问负金额. Python 的负下标会读取列表尾部, 不能用它代替"负金额不可达"的数学约定.

如果把所有初值写成 0, 金额 1 就会被当成不用硬币也能凑出, 后续结果也会被污染. 对最少枚数问题, 不可达应当用正无穷; 它与 0 的含义完全不同.

零面值会使状态依赖自身, 负面值会破坏当前的求值顺序. 若原金额带小数, 应先确定精确的离散单位再换算为整数, 任意四舍五入可能改变可行方案.

28.5.2 为什么只按单位重量评分选择会失误

评分重量比分别为 \(1.5,4/3,1.25,1.6\). 按这个比值从高到低尝试, 先带第 4 件, 再带第 1 件, 总重量 7, 评分 11. 而第 2 件和第 4 件的总重量为 8, 评分 12, 更好.

这说明这条具体贪心规则对 0-1 装备选择不保证最优. 允许物品任意分割时, 问题结构不同, 不能直接搬用相关贪心结论.

28.6 给表格加上阶段: 前两件物品怎样逐行算

定义

\[ D[i,j]=\text{从前 }i\text{ 件物品中选择, 总重量不超过 }j\text{ 的最大评分}. \]

这里同时记录处理到的物品数量 \(i\) 和容量上限 \(j\). 只知道考虑了几件, 不知道容量, 就无法判断后面的装备能否装下. 只知道容量而不保留物品阶段, 也容易把同一件反复使用.

没有物品时, 可以选择空集合, 所以 \(D[0,j]=0\). 下面先只用前两件, 容量上限取 5, 把三行完整打印出来.

MATLAB · step06_prefix_rows.m

表 28-8 前两件装备的状态表.

已处理的物品 容量 0 1 2 3 4 5
0 件 0 0 0 0 0 0
前 1 件 0 0 3 3 3 3
前 2 件 0 0 3 4 4 7

例如最后一格, 不选第 2 件可得 3 分, 选它则从上一行容量 \(5-3=2\) 处取 3 分, 再加 4 分, 得到 7. 两个候选都读取上一行.

一般递推为

\[ D[i,j]=\begin{cases} D[i-1,j],&0\leqslant j<w_i,\\ \max\{D[i-1,j],D[i-1,j-w_i]+v_i\},&w_i\leqslant j\leqslant W. \end{cases} \]

这里 \(w_i\) 为正整数重量, \(v_i\) 为非负评分, \(W\) 为非负整数容量. "选"分支的来源必须是前 \(i-1\) 件, 才能保证当前物品只出现一次. 按物品阶段逐行计算; 在完整二维表中, 同一行的容量可以递增或递减, 因为来源都在上一行.

原问题也可写成前面学过的 0-1 整数规划:

\[ \begin{aligned} &\max_y\quad\sum\limits_{i=1}^{n}v_i y_i,\\ &\mathrm{s.t.}\quad\begin{cases} \sum\limits_{i=1}^{n}w_i y_i\leqslant W,\\ y_i\in\{0,1\},\quad i=1,\ldots,n. \end{cases} \end{aligned} \]

动态规划是按状态递推求解这一离散模型, 本章不需要调用统一的外部优化求解器. 输入假设与状态规模决定这种求法是否合适.

28.8 只留一行以后, 为什么容量要倒着走

二维表的当前行只依赖上一行. 只求最优值时, 可以反复覆盖同一个数组, 但必须保证读取的来源仍属于上一阶段.

先只放一件重量 2, 评分 3 的物品, 容量上限为 4. 每件只有一份, 正确评分应为 3. 分别按倒序和正序更新, 把每步数组都打印出来.

MATLAB · step08_capacity_order.m

倒序先算容量 4, 来源容量 2 还没有放入当前物品, 所以只得到 3. 正序先把容量 2 更新为 3, 到容量 4 时再从这个已更新的格子出发, 又加一次 3, 得到 6. 这个过程已经允许当前物品重复使用.

图 28-4 同一件物品的两种更新顺序. 每行显示一次更新后的整个数组. 倒序保留 0-1 语义, 正序中的来源可能已含当前物品, 因而容量 4 处得到重复使用的评分 6.

0-1 背包的一维更新为

\[ d[j]\leftarrow\max\{d[j],d[j-w_i]+v_i\}, \qquad j=W,W-1,\ldots,w_i. \]

空间由 \(O(nW)\) 降为 \(O(W)\), 时间仍为 \(O(nW)\). 如果还要恢复方案, 应保留二维表或正确的阶段选择记录. 后续覆盖会改变一维格子的历史, 不能默认一组不断修改的父指针仍能还原原来的选择.

这里要求倒序的是压缩后的 0-1 背包容量循环. 不应把它误记成所有动态规划都要倒序, 前面的无限硬币金额恰恰按递增计算.

Python · step09_exact_fill.py

MATLAB · step09_exact_fill.m

容量上限版的初始值为 0, 表示空集合在该容量以内可行. 恰好重量版的正重量初值为负无穷, 表示空集合无法组成它. 后者是最大化评分, 所以用负无穷排除不可达来源; 硬币最少枚数是最小化, 使用的则是正无穷.

数学上, 恰好装满状态可定义为

\[ E[i,j]=\text{从前 }i\text{ 件中选择, 总重量恰好为 }j\text{ 的最大评分}, \]

其初值为

\[ E[0,0]=0,\qquad E[0,j]=-\infty\quad(j>0). \]

完整函数无解时, Python可以返回 None, MATLAB可以返回 -Inf. 这都表示不可达, 不能解释成评分为零.

28.10 一个两阶段分配: 先算后面的最优值, 再决定眼前怎么分

28.10.1 用两份经费做一次完整计算

把 2 份经费分配给社区科普项目 A 和 B. 每份经费的单位相同, 分配量只能是整数. 两个项目的教学评分如下, 总评分按项目相加, 允许保留未用经费, 未用部分不计分.

表 28-11 两项目的分配评分.

分配份数 \(a\) 0 1 2
项目 A 的评分 \(r_1(a)\) 0 3 4
项目 B 的评分 \(r_2(a)\) 0 2 4

先决定 A, 再决定 B. 阶段不表示必须先发生哪项实际活动, 而是组织决策的顺序. 状态 \(s\) 表示当前还剩几份经费, 行动 \(a\) 表示给当前项目几份, 下一状态为 \(s-a\).

完整模型为

\[ \begin{aligned} &\max\quad\sum\limits_{t=1}^{2}r_t(a_t),\\ &\mathrm{s.t.}\quad\begin{cases} s_1=2,\\ a_t\in\{0,1,\ldots,s_t\},\quad t=1,2,\\ s_{t+1}=s_t-a_t,\quad t=1,2,\\ s_t\in\{0,1,2\},\quad t=1,2,3. \end{cases} \end{aligned} \]

定义 \(V_t(s)\) 为从项目阶段 \(t\) 开始, 当前剩余 \(s\) 份经费时, 后续能够得到的最大总评分. 两个项目都处理完后不再有评分, 所以 \(V_3(s)=0\).

最后处理 B, 剩余 0, 1, 2 份时分别最多得到 0, 2, 4 分. 再回到 A 前, 初始有 2 份:

表 28-12 当前分配与后续最优的组合.

给 A 的份数 A 当前评分 留给 B 的份数 B 后续最优评分 合计
0 0 2 4 4
1 3 1 2 5
2 4 0 0 4

若只让 A 的当下评分最高, 会给它两份而得到总分 4. 把当前评分与后续最优评分相加后, 应当各给一份, 总分为 5.

A 前 \(V_1\) 0 3 5

先从后往前算价值, 再从初始状态往前读取选择. 两个方向承担不同任务: 倒推计算"将来最好能得多少", 顺推还原"这一步实际分多少". Python 阶段下标 0, 1 对应数学阶段 1, 2; MATLAB 数组阶段按 1, 2 使用, 但剩余经费列仍需加 1.

28.10.2 从这一次计算读出 Bellman 递推

本例的一般写法为

\[ V_t(s)=\max_{a\in\{0,1,\ldots,s\}} \{r_t(a)+V_{t+1}(s-a)\},\qquad t=2,1, \]

终点条件为 \(V_3(s)=0\). 这种把当前收益与后续最优收益合在一起比较的关系称为 Bellman 递推. 若改为费用最小化, 应相应改成最小值和费用函数.

能否只用剩余经费作为状态, 要看它是否保存了后续需要的信息. 本例项目评分只由该项目分到的份数决定, 已经给 A 多少不需要另记. 若 B 的评分还取决于 A 做过什么活动, 或存在必须搭配的要求, 就要把必要信息加入状态, 不能继续直接套这张表.

硬币例题用金额作为子问题规模, 装备例题用已处理物品与容量, 当前例题用项目阶段与剩余经费. 阶段可以是人为组织的处理顺序, 不必总是真实时间. 相同状态之所以能够合并, 是因为被省略的历史不会再改变后续合法行动与收益.

28.10.3 保存结果, 不意味着状态表总是算得动

动态规划英文为 dynamic programming, 简称 DP. 它既可按依赖顺序填表, 也可用递归加缓存保存已算状态. 固定本章面值和边界规则时, 原朴素递归的函数体执行 1672 次, 记忆化版本首次计算 26 个状态; 下面给出原计数程序. [1]

这不是所有实现都固定具有的次数. 缓存按函数参数保存结果, 面值改变后不能继续使用旧结果; 缓存也不会消除递归深度限制.

二维装备表有 \((n+1)(W+1)\) 个格子, 本例是 \(5\times9=45\) 个. 时间量级 \(O(nW)\) 仍依赖容量的数值大小. 二进制写出 \(W\) 只需约 \(\log_2 W\) 位, 容量状态却约有 \(W\) 个, 所以该算法是伪多项式时间, 不能因此声称一般 0-1 背包已有输入长度意义下的多项式算法. [2]

增加体积, 数量或历史信息后, 状态数可能迅速扩大. 应先估计表格规模, 再选择二维表, 稀疏状态, 整数规划或其他方法. 本章各例的全局最优保证来自正确的状态, 全部合法分支和边界, 不是仅因为程序里写了循环与数组.

28.10.4 结果检查与阅读顺序

  1. 用一句话说清每个格子的含义, 特别区分"恰好"与"不超过".
  2. 在一个具体格子列出所有合法候选, 标明来源位置和新增费用或评分.
  3. 核对空状态, 不可达标记与下标偏移.
  4. 说明来源为什么先得到, 压缩后来源是否仍属于所需阶段.
  5. 把最优值与记录的行动分开检查, 最后回代原金额, 重量与评分.
  6. 用小规模完整枚举或独立界核对, 再估计状态数与每状态工作量.

下一章研究启发式算法. 当正确的精确模型已明确, 但状态空间或组合空间过大时, 需要进一步学习怎样搜索较好的可行方案, 并说明得到的是何种保证.

28.10.5 分步练习

  1. 手算 \(7+7+7+5\) 的金额与剩余量. 这条规则失败, 为什么不能说明金额 27 无解?
  2. 列出凑出 9 的三个最后面值候选. 为什么状态值不等于每个候选值?
  3. 如果错误地把 \(f[1]\) 初始化为 0, 更新金额 3 时会得到什么错误结论?
  4. 按给定记录还原金额 27 的方案. 如果最后一枚改选 7, 能否给出同样最优的数量组合?
  5. 用前 3 件的已知行, 手算容量 7 时第 4 件的选与不选分支.
  6. 只用前两件, 手算 \(D[2,5]\). 为什么选择第 2 件后的来源必须读取上一行?
  7. 核对编号 [2,4] 的重量和评分. 回溯怎样保证第 4 件不被选两次?
  8. 只有重 2, 评分 3 的一件物品时, 写出正序更新容量 2 与 4 的来源. 如果允许同种物品不限量, 评分 6 是否仍然错误?
  9. 只有重 3, 评分 4 的一件物品, 分别要求恰好装满 0, 3, 4. 哪些可行? 应使用什么初值?
  10. 将两阶段科普经费改为总共 1 份, 重新计算最优分配. 再解释本例为什么可以只记录剩余经费而省略此前的完整分配历史.
